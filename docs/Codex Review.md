# Codex Review

دفتر متابعة مراجعة المشروع. هذا الملف لا يعني أن أي تعديل على الكود
مسموح تلقائياً: كل مشكلة تُعرض أولاً مع دليل وإصلاح مقترح، ثم يقرر المالك
إن كان يريد تنفيذ الإصلاح.

## كلمات بسيطة

- **جزء مراجعة:** شيء صغير نفحصه في جلسة واحدة، مثل تسجيل دخول الإدارة.
- **نسخة تجريبية (`staging`):** نسخة منفصلة من الموقع للاختبار، لا تمس الموقع
  الحقيقي ولا بياناته.
- **مشكلة P0:** خطر كبير، مثل وصول غير مصرح إلى الإدارة أو تغيير مبلغ فاتورة.
- **مشكلة P1:** شيء أساسي لا يعمل كما يجب.
- **مشكلة P2:** مشكلة مهمة لا تكسر النظام كله.
- **مشكلة P3:** تحسين أو ملاحظة صغيرة.

## قواعد العمل

- جزء واحد فقط في اليوم.
- نبدأ بالتقرير؛ لا نغير الكود أو قاعدة البيانات أو الإعدادات قبل موافقة صريحة.
- أي اختبار يكتب بيانات أو يرسل رسالة يجري على النسخة التجريبية فقط.
- رسائل الاختبار ترسل إلى بريد يملكه المالك فقط، بعنوان يبدأ بـ `[TEST]`.
- لا يوضع أي بريد شخصي أو كلمة مرور أو مفتاح سري في Git أو في هذا الملف.
- لكل نتيجة: النطاق، ما تم فحصه، الدليل، مستوى الخطورة، الإصلاح المقترح، والقرار.

## بوابة النسخة التجريبية

قبل اختبار لوحة الإدارة أو الفواتير سلوكياً، يجب أن تكون هذه البنود صحيحة:

- [ ] الرابط هو `staging.yamanwarda.de`.
- [x] الوصول محمي لحساب المالك فقط، قبل صفحة تسجيل الدخول إلى التطبيق.
- [ ] لا تظهر النسخة التجريبية في Google أو في `sitemap.xml`.
- [~] لها Worker وقاعدة بيانات وR2 وأسرار منفصلة عن الإنتاج. أنشئ R2 وقاعدة
  Neon وHyperdrive منفصلون؛ Worker والأسرار ما زالت غير جاهزة.
- [ ] قيم `BASE_URL` و`BETTER_AUTH_URL` ومفاتيح Turnstile تخص `staging` وحدها.
- [ ] يوجد حساب مدير تجريبي وبيانات وهمية فقط.
- [ ] البريد الحقيقي، إن اختبرناه، يصل فقط إلى صندوق بريد يملكه المالك وبعلامة `[TEST]`.

### ما يلزم لإكمالها

- قاعدة Neon جديدة فارغة، لا نسخة من قاعدة الإنتاج ولا اتصال بها.
- Cloudflare Access مفعّلة لتُغلق الموقع قبل تسجيل دخول التطبيق.
- أسرار جديدة مستقلة: جلسات الإدارة، حماية النماذج، وتحديد المعدل. لا يعاد
  استخدام أسرار الإنتاج.
- مفتاح Resend خاص بالاختبار أو سياسة إرسال تمنع أي مستلم غير صندوق بريد المالك؛
  كل رسالة تبدأ بـ`[TEST]`.
- Turnstile جديد خاص بـ`staging.yamanwarda.de`.

## قرار الـmodel قبل كل جزء

- الفحص المعتاد: `GPT-6 Astra` مع `medium`.
- الأمن أو المال أو مشكلة صعبة مثبتة: `GPT-6 Astra` مع `xhigh`.
- `max` لا يستخدم إلا إذا بقيت المشكلة بلا جواب بعد الفحص العادي.
- قبل البدء، نراجع `Settings → Usage`. لا نرفع الاشتراك أو نشتري رصيداً قبل أن
  نعرف استهلاك أول جزء حقيقي.

## معلومات نثبتها قبل الحكم

- الـroadmap يضع الفواتير تحت B9 غير المكتمل، بينما قال المالك إن النظام يعمل.
  نثبت واقع الكود والاختبارات قبل وصفه بالمكتمل أو الناقص.
- توجد وثائق قديمة تصف لغة المدونة بطريقة تختلف عن قاعدة اللغات الثلاث الحالية.
  نثبت مصدر الحقيقة قبل فحص SEO أو اقتراح تغيير.
