## الفكرة الأساسية

لا يشتري العميل React أو PostgreSQL أو PostHog. يشتري طريقة أوضح لتنفيذ عملية مهمة في شركته، وبرنامجاً يناسبها عندما لا تكفيه الأدوات الجاهزة.

الرسالة:

> أبني تطبيقات ويب وأنظمة عمل مخصصة تبدأ من مشكلة واضحة ونسخة أولى صغيرة. نفهم العملية، نحدد ما يستحق البناء الآن، ثم أنفذها على مراحل قابلة للفحص بدلاً من بيع نظام ضخم منذ البداية.

> 2.990 Euro ist der Einstieg für ein kleines, klar abgegrenztes Individualprojekt. Der endgültige Preis entsteht erst, wenn Nutzer, Abläufe, Daten, Integrationen und Betrieb bekannt sind.

## كيف نشرح MVP؟

> Wir bauen nicht sofort jede denkbare Funktion. Zuerst entsteht die kleinste produktive Version, die den wichtigsten Ablauf zuverlässig löst. Weitere Funktionen können danach als eigene Phasen folgen.

## كيف نرد على طلب تعديل نظام خارجي؟

> Bevor ich Änderungen an einem bestehenden System übernehme, muss ich Technik, Testmöglichkeiten, Zugänge und Backups sicher beurteilen können. Wenn ich die Auswirkungen nicht zuverlässig prüfen kann, übernehme ich das Risiko nicht.

لا نعتذر عن هذا الحد ولا ندّعي الخبرة في Stack غير مألوف. يمكن اقتراح نظام جديد صغير أو Integration عبر API موثق عندما يكون ذلك آمناً، لكن لا ندخل إلى Production code لا نستطيع السيطرة عليه.

## لماذا لا نعرض باقات كثيرة؟

- النظام لا يُقاس بعدد الصفحات.
- كلمة Dashboard قد تعني شاشة بسيطة أو نظام صلاحيات وتقارير معقداً.
- السعر الثابت قبل معرفة البيانات والتكاملات غالباً غير صادق.
- العميل يحتاج نقطة بداية وعملية واضحة أكثر من قائمة Features طويلة.
